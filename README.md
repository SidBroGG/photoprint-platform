# ФотоПринт · Платформа управления

Локально запускаемый MVP управленческой BI-платформы для производственно-полиграфического бизнеса (фотокниги и индивидуальная фотопродукция). Реализован по `CONTEXT.md`: единое окно по продажам, финансам, клиентам, продуктам, производству, логистике, клиентскому сервису и персоналу, сигналы «что → где → причина → действие», ABC/XYZ, LTV, сезонность, повторные продажи, загрузка мощностей, узкие места, контроль сроков, краткосрочный и долгосрочный прогноз, ролевой доступ.

## Стек

- Next.js 15 (App Router), React 19, TypeScript strict
- MUI 7, MUI X Charts 8, Emotion, Roboto (`@fontsource/roboto`, кириллица)
- Tailwind CSS 4 для layout-утилит
- Bun для установки, dev, тестов и сборки
- Детерминированные мок-данные в памяти, без БД и внешних API

## Запуск

```powershell
bun install
bun dev
```

Откройте `http://localhost:3000` — произойдёт редирект на экран демо-входа.

### Быстрый вход и прямые ссылки

Пароли не нужны: ссылка вида `/api/demo-login/<аккаунт>` сразу ставит сессию и открывает домашний раздел роли. Параметр `next` ведёт на конкретную страницу без переходов по меню (проверяется доступ роли).

```text
http://localhost:3000/api/demo-login/ceo
http://localhost:3000/api/demo-login/sales
http://localhost:3000/api/demo-login/production
http://localhost:3000/api/demo-login/service
http://localhost:3000/api/demo-login/prod-spec
http://localhost:3000/api/demo-login/service-spec
http://localhost:3000/api/demo-login/ceo?next=/production
http://localhost:3000/api/demo-login/sales?next=/customers
```

## Демо-аккаунты

Паролей нет: на `/login` выберите карточку аккаунта. Сервер ставит httpOnly-cookie `pp_session` на 8 часов и определяет роль только на сервере.

| Аккаунт | Роль | Домашний маршрут | Доступ |
|---|---|---|---|
| Анна Смирнова (`ceo`) | Генеральный директор | `/dashboard` | Все разделы и агрегаты |
| Игорь Волков (`sales`) | Руководитель продаж и финансов | `/dashboard` | Обзор, заказы, клиенты, продукты, персонал (продажи), прогноз продаж |
| Мария Кузнецова (`production`) | Руководитель производства | `/dashboard` | Обзор, заказы без сумм, производство, персонал (производство), прогноз загрузки |
| Дмитрий Орлов (`service`) | Руководитель логистики и клиентского сервиса | `/dashboard` | Обзор, заказы без сумм, логистика, сервис, персонал (логистика/сервис), прогноз отправлений |
| Алексей Петров (`prod-spec`) | Специалист производства, стадия «Печать» | `/production` | Только своя очередь на печати |
| Ольга Соколова (`service-spec`) | Специалист клиентского сервиса | `/service` | Только назначенные ей обращения |

Прямой заход на запрещённый URL редиректит на домашний маршрут роли. Проверки выполняются на сервере: `requireSession()` в layout и `requirePage(pageKey)` в каждой странице. Скрытие пунктов меню — только дополнительная мера.

## Сценарий демонстрации

1. **CEO.** Войдите как Анна Смирнова. На `/dashboard` проверьте KPI по всем доменам, сквозной поток «Заказ → Оплата → Производство → Готов → Доставка → Вручён», сигналы с причиной, действием, ответственным и сроком, а также риски прогноза. В `/orders` откройте заказ и его таймлайн. Далее: `/customers` (ABC × XYZ, LTV), `/products` (маржа, сезонность, выбывшие), `/production` (загрузка этапов, узкое место сборки), `/logistics` (поиск по трекингу, задержки), `/service` (SLA), `/personnel` (загрузка и просрочки), `/forecast` (21 день и 3 месяца).
2. **Руководитель производства.** В меню нет клиентов, продуктов, логистики и сервиса. В заказах и деталях нет сумм и маржи. На обзоре только производственные KPI, этапы и сигналы. В прогнозе только спрос vs мощности.
3. **Руководитель продаж.** Доступны продажи, финансы, клиенты, продукты и прогноз продаж. Проверьте сигналы «Ошибка синхронизации оплаты», «Клиент под риском», «Низкая маржа продукта».
4. **Руководитель логистики и сервиса.** Проверьте поиск по номеру отправления, задержки доставки, самовывоз без трекинга и просрочки SLA. Разделов клиентов, продуктов и производства нет.
5. **Специалисты.** У Алексея Петрова доступна только своя очередь на печати и свои просрочки; у Ольги Соколовой — только назначенные обращения. `/dashboard` и чужие URL редиректят на домашний маршрут.
6. **Повторный запуск.** Перезапустите сервер: структура датасета и демо-ситуации воспроизводимы, даты пересчитываются относительно текущего дня.

## Разделы

- `/login` — выбор демо-аккаунта без пароля.
- `/dashboard` — KPI домена, сквозной поток, сигналы, риски прогноза.
- `/orders` и `/orders/[id]` — пайплайн, фильтры, таблица с колонками под роль, таймлайн заказа, оплата и синхронизация, производство, доставка, обращения.
- `/customers` — активные клиенты, повторные продажи, средний LTV, топ-клиенты, матрица ABC × XYZ, таблица с фильтрами.
- `/products` — выручка, маржинальность, выбывшие позиции, повторные заказы, сезонность по месяцам, таблица и список выбывших.
- `/production` — KPI, загрузка этапов и узкие места, просроченные и рискованные заказы; для специалиста — только личная очередь.
- `/logistics` — KPI доставки, поиск по номеру отправления/заказу/клиенту, задержки, ETA, самовывоз.
- `/service` — KPI обращений, SLA, первый ответ, таблица обращений; для специалиста — только свои.
- `/personnel` — численность, загрузка, перегруженные, просроченные задачи по ответственным; срез по направлению.
- `/forecast` — 21-дневный прогноз, спрос vs мощности, риски, месячный тренд и сезонность на 3 месяца.

## Метрики

- **Выручка** — сумма оплаченных заказов (`paid` + `sync_error`) по дате оплаты за период.
- **Маржа** — выручка минус себестоимость; **маржинальность** — маржа / выручка.
- **Средний чек** — выручка / число оплаченных заказов.
- **ABC** — по выручке за 12 месяцев: A — до 80% накопленной выручки, B — до 95%, C — остальные.
- **XYZ** — коэффициент вариации месячного числа заказов за 6 месяцев: X < 0,33, Y < 0,66, Z ≥ 0,66.
- **LTV, факт** — накопленная оплаченная выручка клиента за 12 месяцев.
- **Повторные продажи** — доля заказов клиентов, у которых был предыдущий заказ; для продукта — доля заказов от возвращающихся клиентов.
- **Маржинальность продукта** — (цена − себестоимость) / цена по каталогу.
- **Выбывший продукт** — 0 оплаченных заказов за 60 дней.
- **Загрузка этапа** — активная очередь заказов на этапе / сменная мощность (допечатная подготовка 10, печать 8, сборка 6 заказов/день). **Узкое место** — очередь ≥ мощности.
- **Соблюдение срока производства** — доля завершённых за 30 дней заказов с `productionCompletedAt ≤ dueAt`.
- **Доставка в срок** — доля доставленных за 30 дней с `deliveredAt ≤ eta`; **задержка** — ETA в прошлом и вручения нет.
- **SLA сервиса** — открытые обращения с истёкшим `slaDueAt`; **первый ответ** — среднее время до `firstResponseAt` за 30 дней.
- **Загрузка сотрудника** — активные назначенные задачи / дневная норма; **просрочка** — задачи и обращения с истёкшим сроком.

Периоды фиксированы для MVP: 30 дней, 90 дней, 12 месяцев. Произвольный выбор периода не предусмотрен.

## Прогноз

- **Краткосрочный (21 день):** последние 56 дней истории, линейный тренд методом наименьших квадратов и сезонные коэффициенты дня недели. Значения неотрицательные.
- **Спрос по этапам:** прогноз заказов в день сравнивается со сменной мощностью каждого этапа; дни перегрузки группируются по неделям.
- **Отправления:** прогноз заказов × доля заказов с доставкой за последние 30 дней.
- **Долгосрочный:** 12 месячных точек истории, линейный тренд месяца и сезонный индекс; 3 месяца вперёд.

Это демонстрационная статистика на мок-данных, а не гарантия точности и не ML-модель.

## Сигналы

| Тип | Условие | Действие | Аудитория |
|---|---|---|---|
| Ошибка синхронизации оплаты | `paymentStatus = sync_error` | Повторить синхронизацию, проверить пречек | Продажи, CEO |
| Просрочка производства | активный заказ, `dueAt < now` | Поднять приоритет, назначить ответственного | Производство, CEO |
| Узкое место | очередь этапа ≥ сменной мощности | Перераспределить смену | Производство, CEO |
| Задержка доставки | ETA прошла или статус `delayed` | Связаться с перевозчиком, уведомить клиента | Логистика/сервис, CEO |
| Просрочка SLA | открытое обращение, `slaDueAt < now` | Назначить исполнителя, ответить клиенту | Сервис, CEO |
| Клиент под риском | B2B, падение оборота ≥ 50% и нет заказов 30 дней | Связаться, предложить повторный заказ | Продажи, CEO |
| Низкая маржа | активный продукт, маржа < 25%, есть заказы 30 дней | Пересмотреть цену или себестоимость | Продажи, CEO |
| Риск перегрузки по прогнозу | прогнозный спрос > мощности в ближайшие 14 дней | Запланировать смены, предупредить продажи | Производство, CEO |

ID сигнала стабилен (`тип:объект`). Кнопка «Взять в работу» хранит отметку в `localStorage` браузера; серверной персистентности нет.

## Данные

- Генератор `createDataset(now, seed)` использует seed `20261111` и окно 365 дней; результат детерминирован при одинаковых `now` и seed и пересчитывается относительно текущего дня.
- 40 клиентов, 18 продуктов, 18 сотрудников, ~2,6 тыс. заказов, отправления и обращения.
- Сезонность: выпускные (апрель–июнь), свадьбы (июль–сентябрь), календари и фотокниги (ноябрь–декабрь), будни выше выходных.
- Гарантированные демо-ситуации: очередь сборки выше мощности, 3 просроченных производственных заказа, 2 ошибки синхронизации оплаты, 3 задержки доставки, 3 просрочки SLA, 2 клиента под риском, 1 низкомаржинальный и 2 выбывших продукта, повторные заказы, предпосылки перегрузки в прогнозе.
- Связи и статусы согласованы: оплаченные заказы проходят производственный путь, доставка имеет отправление (кроме самовывоза), обращения привязаны к заказам, назначения ссылаются на существующих сотрудников.
- Форматирование дат, денег и чисел выполняется на сервере (`ru-RU`, RUB, `Europe/Moscow`); клиенту передаются готовые строки и ISO-подобные значения, чтобы избежать hydration mismatch.

## Ограничения MVP

- Демо-вход без паролей и без реальной аутентификации; cookie можно подменить, это не production-безопасность.
- Нет БД и реальных интеграций с Битрикс24, ERP, 1С и HR — все данные мок-детерминированные.
- Отметки «В работе» у сигналов не сохраняются на сервере и сбрасываются при смене браузера/очистке `localStorage`.
- Прогноз — прозрачная статистика на исторических мок-данных, не обещание точности.
- Периоды фиксированы (30/90 дней, 12 месяцев), произвольный выбор не реализован.
- Нет экспорта, уведомлений, настроек, управления пользователями, тёмной темы и мобильного приложения — вне скоупа `CONTEXT.md`.

## Структура

```
src/
  app/                 # маршруты, layout, login, server actions
  components/          # клиентские MUI-компоненты и экраны разделов
  lib/
    auth/              # роли, матрица доступа, cookie-сессия
    data/              # seeded-генератор и кэш датасета
    analytics/         # метрики, ABC/XYZ, операции, персонал, прогноз, сигналы
    view/              # серверные view models для страниц
    format.ts, dates.ts, labels.ts
  theme/theme.ts       # жёлтая Material-тема
  types/domain.ts      # доменная модель
```

Тесты лежат рядом с модулями (`*.test.ts`) и запускаются командой `bun test`.
