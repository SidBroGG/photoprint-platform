# ФотоПринт · Платформа управления

Локально запускаемый MVP управленческой BI-платформы для производственно-полиграфического бизнеса (фотокниги и индивидуальная фотопродукция). Реализован по `CONTEXT.md`: единое окно по продажам, финансам, клиентам, продуктам, производству, логистике, клиентскому сервису и персоналу, канбан проблем по направлениям с приоритетами и ответственными, ABC/XYZ, LTV, сезонность, повторные продажи, загрузка мощностей, узкие места, контроль сроков, краткосрочный и долгосрочный прогноз, ролевой доступ.

## Стек

- Next.js 15 (App Router), React 19, TypeScript strict
- MUI 7, MUI X Charts 8, Emotion, Roboto (`@fontsource/roboto`, кириллица)
- Tailwind CSS 4 для layout-утилит
- Bun для установки, dev, тестов и сборки
- Детерминированные мок-данные в памяти, без БД и внешних API

## Запуск

Production-режим: все страницы компилируются на этапе сборки и открываются сразу.

```powershell
bun install
bun run build
bun run start
```

Откройте `http://localhost:3000` — произойдёт редирект на экран демо-входа.

Режим разработки с компиляцией страниц по мере открытия:

```powershell
bun dev
```

Проверки качества:

```powershell
bun run typecheck
bun test
bun run lint
```

## Сценарий демонстрации

1. **CEO.** Войдите как Анна Смирнова. На `/dashboard` проверьте KPI по всем доменам, сквозной поток «Заказ → Оплата → Производство → Готов → Доставка → Вручён» и риски прогноза. В `/orders` откройте заказ и его таймлайн. Далее: `/customers` (ABC × XYZ, LTV), `/products` (маржа, сезонность, выбывшие), `/production` (загрузка этапов, узкое место сборки), `/logistics` (поиск по трекингу, задержки), `/service` (SLA), `/personnel` (загрузка и просрочки), `/forecast` (21 день и 3 месяца). В `/issues` откройте канбан всех процессов: фильтры по категориям, закрепление задач за собой и смена статусов.
2. **Руководитель производства.** В меню нет клиентов, продуктов, логистики и сервиса. В заказах и деталях нет сумм и маржи. На обзоре только производственные KPI и этапы. В прогнозе только спрос vs мощности. На канбане видны только задачи производства.
3. **Руководитель продаж.** Доступны продажи, финансы, клиенты, продукты и прогноз продаж. На `/issues` проверьте задачи «Синхронизация оплаты», «Клиент под риском» и «Пересмотреть цену фотокниги»: их можно закрепить за собой и перевести по статусам.
4. **Руководитель логистики и сервиса.** Проверьте поиск по номеру отправления, задержки доставки, самовывоз без трекинга и просрочки SLA. На канбане доступны категории логистики и клиентского сервиса. Разделов клиентов, продуктов и производства нет.
5. **Специалисты.** У Алексея Петрова доступна только своя очередь на печати и канбан производства; у Ольги Соколовой — только назначенные обращения и канбан сервиса. `/dashboard` и чужие URL редиректят на домашний маршрут.
6. **Повторный запуск.** Перезапустите сервер: структура датасета, демо-ситуации и стартовый набор задач канбана воспроизводимы, даты пересчитываются относительно текущего дня.

## Разделы

- `/login` — выбор демо-аккаунта без пароля.
- `/dashboard` — KPI домена, сквозной поток, риски прогноза и переход в канбан.
- `/issues` — канбан проблем: категории процессов, статусы, критичность, краткое описание, закрепление за собой. CEO видит все процессы, остальные — только свои.
- `/orders` и `/orders/[id]` — пайплайн, фильтры, таблица с колонками под роль, таймлайн заказа, оплата и синхронизация, производство, доставка, обращения.
- `/customers` — активные клиенты, повторные продажи, средний LTV, топ-клиенты, матрица ABC × XYZ, таблица с фильтрами.
- `/products` — выручка, маржинальность, выбывшие позиции, повторные заказы, сезонность по месяцам, таблица и список выбывших.
- `/production` — KPI, загрузка этапов и узкие места, просроченные и рискованные заказы; для специалиста — только личная очередь.
- `/logistics` — KPI доставки, поиск по номеру отправления/заказу/клиенту, задержки, ETA, самовывоз.
- `/service` — KPI обращений, SLA, первый ответ, таблица обращений; для специалиста — только свои.
- `/personnel` — численность, загрузка, перегруженные, просроченные задачи по ответственным; срез по направлению.
- `/forecast` — 21-дневный прогноз, спрос vs мощности, риски, месячный тренд и сезонность на 3 месяца.

## Метрики

- **Выручка** — сумма оплаченных заказов (`paid` + `sync_error`) по дате оплаты за период.
- **Маржа** — выручка минус себестоимость; **маржинальность** — маржа / выручка.
- **Средний чек** — выручка / число оплаченных заказов.
- **ABC** — по выручке за 12 месяцев: A — до 80% накопленной выручки, B — до 95%, C — остальные.
- **XYZ** — коэффициент вариации месячного числа заказов за 6 месяцев: X < 0,33, Y < 0,66, Z ≥ 0,66.
- **LTV, факт** — накопленная оплаченная выручка клиента за 12 месяцев.
- **Повторные продажи** — доля заказов клиентов, у которых был предыдущий заказ; для продукта — доля заказов от возвращающихся клиентов.
- **Маржинальность продукта** — (цена − себестоимость) / цена по каталогу.
- **Выбывший продукт** — 0 оплаченных заказов за 60 дней.
- **Загрузка этапа** — активная очередь заказов на этапе / сменная мощность (допечатная подготовка 10, печать 8, сборка 6 заказов/день). **Узкое место** — очередь ≥ мощности.
- **Соблюдение срока производства** — доля завершённых за 30 дней заказов с `productionCompletedAt ≤ dueAt`.
- **Доставка в срок** — доля доставленных за 30 дней с `deliveredAt ≤ eta`; **задержка** — ETA в прошлом и вручения нет.
- **SLA сервиса** — открытые обращения с истёкшим `slaDueAt`; **первый ответ** — среднее время до `firstResponseAt` за 30 дней.
- **Загрузка сотрудника** — активные назначенные задачи / дневная норма; **просрочка** — задачи и обращения с истёкшим сроком.

Периоды фиксированы для MVP: 30 дней, 90 дней, 12 месяцев. Произвольный выбор периода не предусмотрен.

## Прогноз

- **Краткосрочный (21 день):** последние 56 дней истории, линейный тренд методом наименьших квадратов и сезонные коэффициенты дня недели. Значения неотрицательные.
- **Спрос по этапам:** прогноз заказов в день сравнивается со сменной мощностью каждого этапа; дни перегрузки группируются по неделям.
- **Отправления:** прогноз заказов × доля заказов с доставкой за последние 30 дней.
- **Долгосрочный:** 12 месячных точек истории, линейный тренд месяца и сезонный индекс; 3 месяца вперёд.

Это демонстрационная статистика на мок-данных, а не гарантия точности и не ML-модель.

## Канбан проблем

Канбан заменяет прежние сигналы: вместо пассивного списка отклонений руководитель и сотрудник работают с задачами в общем процессе.

- **Колонки статусов:** «Новые» → «В работе» → «Решено». Статус меняется перетаскиванием карточки или через выпадающий список в окне редактирования задачи.
- **Категории процессов:** «Продажи», «Производство», «Логистика», «Клиентский сервис». Категория фиксируется при создании задачи и определяет, кому она видна.
- **Критичность:** «Низкая», «Средняя», «Высокая», «Критичная». Задаёт цвет карточки и приоритет сортировки внутри колонки.
- **Карточка задачи:** название, критичность, ответственный и кнопка «Закрепить/Открепить». Остальные детали доступны в окне редактирования задачи.
- **Действия:** создать задачу, закрепить свободную задачу за собой, снять закрепление, изменить статус, название, описание и критичность.

Видимость по ролям:

| Роль | Категории канбана |
|---|---|
| Генеральный директор | Все процессы, с фильтром «Все процессы» и по каждой категории |
| Руководитель продаж и финансов | Продажи |
| Руководитель производства, специалист производства | Производство |
| Руководитель логистики и клиентского сервиса | Логистика и клиентский сервис |
| Специалист клиентского сервиса | Клиентский сервис |

Ограничения проверяются на сервере: нельзя создать задачу или изменить чужую категорию, закрепить задачу, которая уже занята другим сотрудником, или снять её с другого сотрудника. Состояние хранится в памяти процесса сервера: изменения видны всем демо-аккаунтам до перезапуска. Базы данных, истории изменений, вложений и уведомлений нет.

## Данные

- Генератор `createDataset(now, seed)` использует seed `20261111` и окно 365 дней; результат детерминирован при одинаковых `now` и seed и пересчитывается относительно текущего дня.
- 40 клиентов, 18 продуктов, 18 сотрудников, ~2,6 тыс. заказов, отправления и обращения.
- Сезонность: выпускные (апрель–июнь), свадьбы (июль–сентябрь), календари и фотокниги (ноябрь–декабрь), будни выше выходных.
- Гарантированные демо-ситуации: очередь сборки выше мощности, 3 просроченных производственных заказа, 2 ошибки синхронизации оплаты, 3 задержки доставки, 3 просрочки SLA, 2 клиента под риском, 1 низкомаржинальный и 2 выбывших продукта, повторные заказы, предпосылки перегрузки в прогнозе.
- Канбан стартует с 16 задач: по 4 на каждую категорию, с разными статусами, критичностью и частью незакреплённых карточек.
- Связи и статусы согласованы: оплаченные заказы проходят производственный путь, доставка имеет отправление (кроме самовывоза), обращения привязаны к заказам, назначения ссылаются на существующих сотрудников.
- Форматирование дат, денег и чисел выполняется на сервере (`ru-RU`, `be-BY`, BYN, `Europe/Moscow`); клиенту передаются готовые строки и ISO-подобные значения, чтобы избежать hydration mismatch.

## Ограничения MVP

- Демо-вход без паролей и без реальной аутентификации; cookie можно подменить, это не production-безопасность.
- Нет БД и реальных интеграций с Битрикс24, ERP, 1С и HR — все данные мок-детерминированные.
- Канбан хранится в памяти сервера: изменения общие для демо-сессий до перезапуска, после перезапуска возвращается стартовый набор задач.
- Прогноз — прозрачная статистика на исторических мок-данных, не обещание точности.
- Периоды фиксированы (30/90 дней, 12 месяцев), произвольный выбор не реализован.
- Нет экспорта, уведомлений, настроек, управления пользователями, истории изменений задач, тёмной темы и мобильного приложения — вне скоупа `CONTEXT.md`.

## Структура

```
src/
  app/                 # маршруты, layout, login, server actions
  components/          # клиентские MUI-компоненты и экраны разделов
  lib/
    auth/              # роли, матрица доступа, cookie-сессия
    board/             # категории, видимость, стор и операции канбана
    data/              # seeded-генератор и кэш датасета
    analytics/         # метрики, ABC/XYZ, операции, персонал, прогноз
    view/              # серверные view models для страниц
    format.ts, dates.ts, labels.ts
  theme/theme.ts       # жёлтая Material-тема
  types/domain.ts      # доменная модель
  types/board.ts       # модель задач канбана
```

Тесты лежат рядом с модулями (`*.test.ts`) и запускаются командой `bun test`.
